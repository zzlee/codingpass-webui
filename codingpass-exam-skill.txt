# CodingPass 智慧出題 Agent 指南 (AGENTS.md)

本文件定義了 **CodingPass（程式學習與自動評測平台）** 的完整出題規範、TeDa 專用語言規範與自動化出題工作流程。 當教師以自然語言描述一道程式題目時，Agent 應依據本指南，自動產出符合 CodingPass 平台後台要求的全套出題檔案，並歸類存放於專屬目錄中。

> [!IMPORTANT] **工作目錄規範**：出題與檔案存放之指定工作目錄為**雲端硬碟下的 `CodingPass` 目錄**。所有題目均存放於 `CodingPass/Pxxxx_[題名]/` 下。
> 
> **檔案原始格式規範（嚴禁轉包裝）**：所有生成的 `.txt`、`.md`、`.teda`、`.cpp` 等檔案，必須**維持其原生純文字/程式碼格式寫入與保存，嚴禁自動轉檔或封裝成 Google Docs（文件）或 Google Sheets（試算表）等雲端應用格式**。
> 
> **輸出精簡核心原則**：除產生的題目 **PDF 題本文檔** 外，其餘所有檔案（`.teda`、`.cpp`、`.txt` 等）皆**以精簡輸出為主，不需要額外說明**。嚴禁在這些檔案中加入冗長註解或非必要的文字解說，且**不產出任何多餘的說明文檔**（如 `.md` 出題說明等）。

---

## 1. 系統核心架構與概念

### 1.1 評測雙軌機制 (Dual-Run)

在 CodingPass 平台中，隨機測資並不需要在測資腳本中手寫答案（參考：[CodingPass 系統手冊](https://www.codingpass.com/doc/doc-codingpass.html)）：

1. **輸入生成**：系統透過 TeDa 隨機測資腳本（`庫題卡測資０隨輸入`）動態生成輸入資料 `_stdin`。
2. **答案生成**：系統將 `_stdin` 餵給教師提供的「正解標竿程式」（`庫題卡碼文標碼`）動態執行，產出標準答案 `_ansout`。
3. **學生執行**：系統將同一份 `_stdin` 餵給學生程式執行，產出學生輸出 `_stdout`。
4. **比對評分**：系統比對 `_stdout` 與 `_ansout`（可配合自訂批改腳本 `庫題卡測資評判輸出`）。
5. **原始碼靜態檢查**：系統透過 TeDa 語量腳本（`庫題卡碼文限碼`）對學生原始碼進行白箱語法結構與防弊檢查。

### 1.2 工作目錄與題目資料夾目錄結構

為便於題目管理與後台批次上傳，**指定工作根目錄為遠端硬碟下的 `CodingPass` 目錄**。**每一道題目所產生的所有檔案，必須統一收納於 `CodingPass/Pxxxx_[題名]` 的專屬資料夾中**（例如 `CodingPass/P1205_區間質數/`）。

目錄結構與 CodingPass 後台欄位對照表如下：

```text
CodingPass/
└── Pxxxx_[題名]/
    ├── Pxxxx_[題名].pdf                 # 【庫題卡文檔】(附件) - A4單頁題本文檔 (唯一需完整排版與說明的文檔)
    ├── Pxxxx_庫題卡測資０隨輸入.teda     # 【庫題卡測資０隨輸入】 - TeDa 隨機測資生成腳本 (原生.teda純文字檔，精簡腳本)
    ├── Pxxxx_庫題卡碼文標碼.cpp          # 【庫題卡碼文標碼】 - C++ (或 Python) 標竿正解 (原生.cpp代碼檔，精簡代碼)
    ├── Pxxxx_庫題卡碼文限碼.txt          # 【庫題卡碼文限碼】 - TeDa 語量檢查 (原生.txt純文字檔，純規則指令)
    ├── Pxxxx_庫題卡測資範例.txt          # 【庫題卡測資範例】 - 題本靜態範例輸入與輸出 (原生.txt純文字檔，純測資文字，分為輸入與輸出兩大獨立區塊，不交錯)
    └── Pxxxx_庫題卡測資評判輸出.teda      # 【庫題卡測資評判輸出】 - (選填) 自訂比對評分腳本 (原生.teda純文字檔，精簡腳本)
```

| 檔案名稱命名規範 | 對應後台欄位 | 格式 / 語言 | 輸出風格與說明 |
| :--- | :--- | :--- | :--- |
| `Pxxxx_[題名].pdf` | **庫題卡文檔** (附件) | PDF (A4單頁) | **完整題本**：包含題意敘述、輸入輸出規範與排版範例。 |
| `Pxxxx_庫題卡測資０隨輸入.teda` | **庫題卡測資０隨輸入** | TeDa 測試腳本 (.teda 原生格式) | **精簡**：純隨機測資生成邏輯，不添加多餘註解，不使用 Google 雲端格式封裝。 |
| `Pxxxx_庫題卡碼文標碼.cpp` | **庫題卡碼文標碼** | C++ (或 Python) (.cpp 原生格式) | **精簡**：正解標竿程式，俐落簡潔，僅保留核心解題代碼。 |
| `Pxxxx_庫題卡碼文限碼.txt` | **庫題卡碼文限碼** | TeDa 語量腳本 (.txt 原生格式) | **精簡**：原始碼結構檢查，每行一條規則指令，不加文字解說，維持純文字。 |
| `Pxxxx_庫題卡測資範例.txt` | **庫題卡測資範例** | 純文字 (.txt 原生格式) | **精簡**：靜態範例資料，明確拆分為「輸入」與「輸出」兩獨立區塊，切勿交錯或使用試算表格式。 |
| `Pxxxx_庫題卡測資評判輸出.teda` | **庫題卡測資評判輸出** | TeDa 批改腳本 (.teda 原生格式) | *(選填)* **精簡**：自訂評分比對邏輯（管線或純 JS 函式）。 |

### 1.3 輸出精簡與格式原生規範 (Concise & Native Format Principle)

為確保後台檔案乾淨利落、便於直接載入且避免混淆，必須貫徹以下規範：

1. **嚴禁轉換為 Google Doc / Sheet 格式**：產生的 `.txt`、`.md`、`.teda` 等檔案，必須直接以原生純文字（Plain Text）或對應副檔名保存，不可透過 Google Drive API 或任何方式包裝成 Google Docs 文件或 Google Sheets 試算表。
2. **除 PDF 外皆為系統檔案**：只有 `Pxxxx_[題名].pdf` 是給學生與教師閱讀的完整題面排版；其餘檔案均為給平台系統載入、解析與執行的配置檔案。
3. **拒絕非必要註解與文字修飾**：程式碼與腳本檔案（`.cpp`, `.teda`, `.txt`）不應加入大量的長篇說明、概念推導或重複性備註。
4. **不產生額外說明文檔**：**切勿額外產生 `出題設定說明.md` 或類似的說明檔案**。所有出題配置在專屬資料夾及對應檔名中已一目了然。
5. **Agent 對話回覆精簡化**：在向教師交付出題結果時，直接精要條列產出的各檔案路徑與核心參數，不進行冗長的逐字複述。

## 2. TeDa 專用語言語法規範

### 2.1 測資生成語言 (TeDa-Testing)

詳見官方文件：[TeDa-Testing Script 手冊](https://www.codingpass.com/doc/doc-teda-testing.html)

TeDa 是基於 JavaScript 擴充的隨機輸出描述語言：

- **輸出與執行**：
  - `;`（分號）具有強烈輸出暗示。
  - `@敘述`：僅執行、不列印（例如 `@A = 100;`）。
  - `s;` 輸出空白、`s(k);` 輸出 $k$ 個空白。
  - `n;` 輸出換行、`n(k);` 輸出 $k$ 個換行。
- **隨機區間與進制**：
  - `A~B`：在 $A$ 到 $B$ 之間隨機取一數值（含端點）。
  - `A~B:step`：等間隔取值（如 `0~999:2` 隨機取偶數）。
- **多筆重複與陣列結構**：
  - `[筆數;格式]{ 敘述 }`：生成多筆資料。**隨機輸入預設產出 30～50 筆**（例如 `[30~50;enn]`），確保測資具備足夠代表性與測試覆蓋率。
  - **格式符號**（前中後格式）：
    - `enn`：首無空、項間換行、尾換行（多行輸入最常用）。
    - `ene`：首無空、項間換行、尾不換行。
    - `esn`：首無空、項間空白、尾換行（單行多數最常用）。
    - `csse`：`c` 表示在開頭印出該維度元素數量。
- **機率權重分配 (`P`)**：
  - 同一區塊內多個 `P(機率){ ... }` 會自動加總並重新分配權重。
  - 用於確保隨機測資能夠均勻涵蓋常規案例與各類邊界條件（例如平閏年、無解情境、極值）。
  - 範例：
    ```javascript
    [30~50;enn]{
      let A = 1~1000, B = 1~1000;
      P(0.2){ @A = 1; @B = 1; }            // 邊界條件
      P(0.4){ @A = 200~300; @B = 100; }    // 反向區間
      P(0.4){ @A = 1000~50000; @B = 5000; }// 大數區間
      A + " " + B;
    };
    ```
- **字串補零與格式化**：
  - 兩位數補零寫法：`M < 10 ? "0" + M : "" + M`

### 2.2 語量檢查語言 (TeDa-Wording)

詳見官方文件：[TeDa-Wording Script 手冊](https://www.codingpass.com/doc/doc-teda-wording.html)

用於對學生的原始程式碼進行靜態結構檢查與防作弊：

- **語法結構**：
  - `#指令[數量/範圍; 參數S] 比對文句`
- **常用指令**：
  - `#term[數量]`：完整單詞比對（Token 精確匹配）。
  - `#root[數量]`：字根／子字串比對（如 `sort` 也會匹配 `stable_sort`）。
  - `#regex[數量; 參數S] 正規表示式`：正規表達式比對。**當需要邏輯 OR（二選一）時必須使用此指令**。
- **常用參數**：
  - `skipComments`：略過註解（避免學生寫在註解中被誤判）。
  - `skipStrings`：略過字串常數（避免字串中包含該詞被誤判）。
  - `skipSpaces`：略過空格。
- **標準防弊與結構限制範例**：
  ```text
  #term[0;skipComments skipStrings] system
  #term[0] <chrono>
  #term[0] <ctime>
  #regex[1~*;skipComments skipStrings] \b(for|while)\b
  ```
  *(注：`[0]` 表示禁詞；`[1~*]` 表示至少出現一次)*

### 2.3 批改評判語言 (TeDa-Scoring)

詳見官方文件：[TeDa-Scoring Script 手冊](https://www.codingpass.com/doc/doc-teda-scoring.html)

用於自訂比對與評分邏輯。環境中注入變數：`_stdin`、`_stdout`、`_ansout`、`_stdarg`：

- **管線比對式 (Pipeline)**： 同時對 `_stdout` 與 `_ansout` 進行正規化後比對：
  ```javascript
  // 逐行比對並去除行末多餘空格
  lines().replace(/\s+$/g, "");
  ```
- **JavaScript 腳本式**： 以 `language=javascript;` 開頭，撰寫完整 JS 條件式，回傳布林值：
  ```javascript
  language=javascript;
  function clean(s) {
    return s.trim().split('\n').map(l => l.trimEnd()).join('\n');
  }
  clean(_stdout) === clean(_ansout);
  ```

## 3. PDF 題本文檔排版規範

CodingPass 的題目 PDF（例如 `P1204萬年月曆.pdf`）具備固定的排版視覺規範：

1. **紙張規範**：A4 直向單頁，邊界約 `18mm 20mm 15mm 20mm`。
2. **標題 (Title)**：
   - 居中，黑色粗體（約 20pt~24pt），格式為 `Pxxxx [題名]`。
3. **前言與題意敘述**：
   - 首行縮排 2 字符，兩端對齊（Justify），行距約 1.55。
4. **章節小標題（深紅特色）**：
   - 字體顏色：`#c00000`（深紅），粗體（約 12pt~14pt）。
   - 固定四個標準小節：
     1. `<div class="section-title">輸入說明</div>`
     2. `<div class="section-title">輸出說明</div>`
     3. `<div class="section-title">範例輸入</div>`
     4. `<div class="section-title">範例輸出</div>`
5. **範例輸入與輸出呈現**：
   - 必須使用等寬字型（如 `Noto Sans Mono CJK TC`, `Courier New`）並置於 `<pre>` 區塊內，保證單一空格與多行排版不折疊。
   - **分區呈現原則**：範例必須嚴格分為「範例輸入」與「範例輸出」兩獨立區塊呈現，**嚴禁將輸入與輸出交錯穿插**（例如避免「輸入 1 → 輸出 1 → 輸入 2 → 輸出 2」）。所有的範例輸入應完整展示在「範例輸入」區塊中，所有對應的範例輸出完整展示在「範例輸出」區塊中。
6. **字型設定**：
   - 優先採用 Traditional Chinese 思源系列字型：`Noto Serif CJK TC`、`AR PL UMing TW`。

## 4. 自然語言出題自動生成工作流程 (Agent Workflow)

當教師向 Agent 提出出題需求時，Agent 必須依照以下標準流程自動產出完整配套檔案：

### Step 1: 題目規格化與細節確認

- 解析教師描述，確定：
  - **題號與題名**（自動編號或自訂，如 `P1205 區間質數`）。
  - **題目敘述**（嚴謹、無歧義的定義與題目背景）。
  - **輸入規格**（多筆或單筆、資料型態、邊界範圍如 $1 \le N \le 10^5$、特殊反向或異常狀況）。
  - **輸出規格**（空格間隔、無解時的輸出如 `None` 或 `-1`、換行規則）。
  - **設計具代表性的範例資料**（至少 3~5 組，涵蓋邊界，且範例資料必須清楚分成輸入區塊與輸出區塊，不得交錯）。

### Step 2: 建立專屬題目資料夾（工作目錄：遠端硬碟下的 CodingPass）

- 於遠端硬碟的 `CodingPass` 工作目錄下，建立專屬題目目錄：`CodingPass/Pxxxx_[題名]/`（例如 `mkdir -p CodingPass/P1205_區間質數`）。
- 後續所有檔案皆直接生成至該專屬目錄下。

### Step 3: 撰寫標準正解標碼 (`Pxxxx_庫題卡碼文標碼.cpp`)

- 撰寫 C++ 完整解答，存入題目資料夾：
  - 必須包含完整的 I/O 處理迴圈（如 `while (cin >> ...)`）。
  - 程式碼需簡潔乾淨、模組化，避免多餘註解與贅述。

### Step 4: 撰寫 TeDa 隨機測資腳本 (`Pxxxx_庫題卡測資０隨輸入.teda`)

- 存入題目資料夾，精簡產出：
  - **隨機測資筆數預設設定為 30～50 筆**（使用 `[30~50;enn]`），確保測資充足且具備多樣性。
  - 使用 `P(機率)` 涵蓋邊界案例、特殊順序與常規隨機案例。
  - 確保輸出格式完全對齊輸入說明，維持原生純文字 `.teda` 格式，無多餘說明。

### Step 5: 撰寫 TeDa 語量檢查腳本 (`Pxxxx_庫題卡碼文限碼.txt`)

- 存入題目資料夾，純規則指令（每行一條）：
  - 基礎防弊：`#term[0;skipComments skipStrings] system`
  - 若要求迴圈：`#regex[1~*;skipComments skipStrings] \b(for|while)\b`
  - 若要求遞迴禁止迴圈：`#term[0] for`、`#term[0] while`
  - 若禁止特定庫：`#term[0] <ctime>` 等。
  - 保持純文字 `.txt` 原生格式，嚴禁加入自然語言文字說明。

### Step 6: 產生範例文字、評分腳本與題本 PDF

- 於題目資料夾內產出剩餘必備檔案（**維持原生檔案格式，除 PDF 外一律精簡輸出，切勿產生多餘說明文件或轉為 Google 文件/試算表**）：
  1. `Pxxxx_[題名].pdf`（利用 HTML+LibreOffice 自動渲染 A4 單頁 PDF，為唯一包含完整題意排版的文檔，範例輸入與輸出分成獨立小節區塊展示）。
  2. `Pxxxx_庫題卡測資範例.txt`（純文字靜態範例資料，**必須分成「輸入」與「輸出」兩個區塊，所有範例輸入置於第一區塊、所有範例輸出置於第二區塊，兩區塊彼此獨立，不得將每筆輸入輸出交錯混編，嚴禁存成試算表格式**）。
  3. `Pxxxx_庫題卡測資評判輸出.teda`（若需自訂容錯，提供極簡比對邏輯，維持原生 `.teda` 格式）。

## 5. 出題品質檢驗清單 (Checklist)

在產出檔案交付給教師前，Agent 必須確認：

- [ ] **原生格式保持（無 Google Doc/Sheet 包裝）**：所有生成的 `.txt`、`.md`、`.teda`、`.cpp` 均保持原生副檔名與純文字格式，未轉檔或封裝為 Google Docs 或 Sheets。
- [ ] **工作目錄與專屬資料夾集中**：題目配套檔案全部集中於遠端硬碟的 `CodingPass/Pxxxx_[題名]/` 資料夾中，未散落於其他路徑或根目錄。
- [ ] **精簡輸出檢核**：除題本文檔（PDF）具備完整題意與排版外，其餘所有檔案（`.teda`, `.cpp`, `.txt`）皆為精簡核心內容，無冗贅註解或解說，且**未產出任何額外的說明文件（如 `.md` 說明文檔）**。
- [ ] **隨機測資筆數檢核**：隨機輸入腳本採用 `[30~50;enn]` 生成 30～50 筆測試資料，充分覆蓋邊界與常規案例。
- [ ] **範例測資分區不交錯**：無論是題本 PDF 或是 `Pxxxx_庫題卡測資範例.txt`，範例資料皆嚴格拆分為「輸入」與「輸出」兩獨立區塊（所有輸入集中在前、所有輸出集中在後），嚴禁交錯混雜。
- [ ] **PDF 單頁規範**：題本 PDF 在預覽中完美收納為 **單頁 A4**，文字未溢出至第二頁。
